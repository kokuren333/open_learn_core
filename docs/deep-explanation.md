# Deep Explanation v1.8

v1.8の目的は、`basis`の文字数を増やすことではなく、初学者が具体例から形式的定義へ移り、定義を使って判断し、誤解を修正できる学習単位にすることです。

Explanation Writerは次の順序を契約とします。

`learner state → why → concrete case → failure cases → pattern → vocabulary → exact definition → unpacking → reapply → near-miss → worked reasoning → misconception → connection → recap`

各段落には一つの役割を与えます。記号や前提語を先に定義し、計算の決定的な中間段階を省略しません。「明らか」「自明」は説明の代わりに使いません。

長さは補助的な指標です。motivation、intuition、formal definition、worked exampleにはソフトな深さ基準がありますが、semantic auditが具体性・橋渡し・非反復性を確認します。
