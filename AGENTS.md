# Open Learn Core contributor guide

- Keep reusable implementation in `core/`; keep subject matter in `domains/<domain>/`.
- Add or update a domain manifest before adding domain content.
- Run domain validation, domain tests, the full test suite, and an all-domain build before publishing.
- Do not place working artifacts in `dist/` or domain-specific assumptions in Core modules.

See [docs/domain-system.md](docs/domain-system.md), [docs/repository-layout.md](docs/repository-layout.md), and [docs/migration.md](docs/migration.md) for the repository contracts.
